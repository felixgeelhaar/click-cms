# Click administration in English and German

The **Interface language / Sprache** selector changes the administration language. It is available before sign-in and on every screen, including the required password-change screen. Click follows the browser language initially; a manual choice is saved in this browser. Switching language updates the current interface without discarding edits or changing the content language.

The interface includes navigation, screen titles, forms, buttons, accessible labels, empty states, confirmation dialogs, publication and review states, schedules, media warnings, security checks, settings, updates, collections, and the visual builder. Dates and language names follow the selected interface language. Technical identifiers, paths, version numbers, and product names retain their spelling.

Authored titles, body text, comments, filenames, account names, plugin descriptions, release notes, and site-defined field or section labels remain exactly as supplied. Interface language and a page's content language are independent. Custom extension interfaces need their own translations.

Unexpected server or plugin errors show German recovery guidance with an expandable **Technische Details** control. The original diagnostic remains available there for support; it is rendered as text, never HTML. English preserves the original diagnostic. API responses and stored documents are unchanged. Image recommendations use the server's quality verdict and dimensions.

## Adding interface text

Use `message('English interface text')` at a display point and add its German translation to `admin-ui/src/lib/locales/de.json`. Use parameters for counts and authored values, for example `message('Delete {0}', [page.title])`. Do not translate model values, API payloads, route identifiers, or arbitrary content. Stored English action notices are translated when displayed, so an existing notice also follows a language switch. The helper supports matching parameterized notices generated by current APIs and existing components.

For errors, use `LocalizedError` instead of interpolating raw diagnostics. Add known errors or parameterized validation patterns to `admin-ui/src/lib/messages.js`. Use `imageQualityMessage()` for server image verdicts.
